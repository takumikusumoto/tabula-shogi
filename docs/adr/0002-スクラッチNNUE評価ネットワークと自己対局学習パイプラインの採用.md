# 0002. スクラッチ NNUE 評価ネットワークと自己対局学習パイプラインの採用

- **ステータス**: 承認済み (Accepted)
- **決定日**: 2026-09-13
- **文脈**: Phase 4 におけるニューラルネットワーク評価関数（NNUE）および強化学習パイプラインの設計方針

## 課題と背景

TabulaShogi では Phase 1〜2 で手動評価関数（HCE: 駒得・PST・玉安全性・手番ボーナス）を採用し、Phase 3 で自己対局および Texel Tuning による HCE パラメータ最適化を構築しました。
しかし、より高度な駒の利き・連携・玉形の相対関係をモデル化するためには、多層ニューラルネットワーク（NNUE）の導入が不可欠です。
一方で、外部クレート（PyTorch, ONNX, ndarray, serde 等）や公開学習済みモデル（やねうら王重み等）の導入は、本プロジェクトの根幹である「ゼロ外部依存（Zero External Dependencies）」および「白紙原則（Tabula Rasa）」に抵触します。

## 決定事項

1. **完全スクラッチ NNUE バックプロパゲーション学習器の実装**:
   - 外部機械学習ライブラリを一切導入せず、Rust 標準ライブラリ `std` のみで連鎖律に基づく微分・勾配計算・Adam オプティマイザをスクラッチ実装する。
2. **ネットワーク構造**:
   - 入力層: 1,386 次元（盤上駒 81マス × 14駒種 + 持ち駒 7種 × 2手番 × 18枚）
   - 隠れ層: 128 ニューロン、活性化関数 ClippedReLU（0.0 〜 1.0、推論時整数 0 〜 127）
   - 出力層: 256 入力（先手128 + 後手128） ➜ 1 スコア（センチポーン変換）
3. **16-bit 整数量子化と独自バイナリ規格 (`TABU_NN1`)**:
   - 推論の超高速化およびメモリ効率のため、16-bit 整数演算（SIMDフレンドリー）への量子化を採用。
   - モデルサイズは約 355 KB（355,604 bytes）の固定バイナリ形式とし、外部シリアライザに依存せず自律的に入出力する。
4. **デュアル評価機構（HCE / NNUE）の共存**:
   - USI オプション `Eval_Type` (HCE / NNUE) および `NNUE_File` により、ユーザーが動的に評価モードを切り替え可能とする。
   - マルチスレッド並列探索（Lazy SMP）において、`Arc<NNUEEvaluator>` によるゼロコピー共有を採用し、メモリオーバーヘッドを防ぐ。

## 結果と影響

- 外部依存ゼロのまま、自己対局データ（TSV）から自動的にニューラルネットワーク評価関数を学習・更新できる自己完結型パイプラインが完成した。
- 将棋GUIやUSIプロトコルとの完全な互換性を維持したまま、HCE と NNUE の相互比較や世代交代検定が可能となった。
